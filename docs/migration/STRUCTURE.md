# JS9 Structure Baseline

This file tracks the incremental structure cleanup during migration.

## Current Rule

- Legacy runtime entrypoint names at repository root remain stable for compatibility.
- New modular code goes under `node/` by runtime target (`node/cli`, `node/helper`, `node/browser`).

## Current Layout

- `node/cli/`:
  - `js9Regions.ts` (source of truth)
  - `js9Regions.js` (generated by TypeScript build)
  - `js9Msg.js` (source of truth, JavaScript during transition)
- `node/browser/`:
  - `js9.js` (viewer core source of truth, JavaScript during transition)
  - `js9worker.js` (worker source of truth, JavaScript during transition)
  - `js9PostMessage.js` (source of truth, browser module during transition)
- `node/helper/`:
  - `js9Helper.js` (source of truth, JavaScript during transition)

- Root compatibility wrappers:
  - `js9.js` symlinks to `node/browser/js9.js`
  - `js9worker.js` symlinks to `node/browser/js9worker.js`
  - `js9Regions.js` forwards to `node/cli/js9Regions.js`
  - `js9Msg.js` forwards to `node/cli/js9Msg.js`
  - `js9Helper.js` forwards to `node/helper/js9Helper.js`
  - `js9PostMessage.js` symlinks to `node/browser/js9PostMessage.js`

## Next Candidate Moves

- Carve first browser-core utility block from `node/browser/js9.js` into `node/browser/core/` (pure helpers only, no behavior change).

Each move should preserve current root entrypoint filenames via small wrappers or symlinks until old build/install paths are retired.

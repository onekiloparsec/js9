# JS9 Structure Baseline

This file tracks the incremental structure cleanup during migration.

## Current Rule

- Legacy runtime entrypoint names at repository root remain stable for compatibility.
- New modular code goes under `node/` by runtime target (`node/cli`, `node/helper`, `node/browser`).

## Current Layout

- `node/cli/`:
  - `regions.ts` (source of truth)
  - `regions.js` (generated by TypeScript build)
  - `msg.js` (source of truth, JavaScript during transition)
- `node/browser/`:
  - `viewer.js` (viewer core source of truth, JavaScript during transition)
  - `worker.ts` (worker source of truth)
  - `worker.js` (generated by TypeScript build)
  - `postMessage.js` (source of truth, browser module during transition)
  - `core/basicUtils.js` (source of truth for extracted pure utility helpers)
- `node/helper/`:
  - `helper.js` (source of truth, JavaScript during transition)

- Root compatibility wrappers:
  - `js9.js` symlinks to `node/browser/viewer.js`
  - `js9worker.js` symlinks to `node/browser/worker.js`
  - `js9Regions.js` forwards to `node/cli/regions.js`
  - `js9Msg.js` forwards to `node/cli/msg.js`
  - `js9Helper.js` forwards to `node/helper/helper.js`
  - `js9PostMessage.js` symlinks to `node/browser/postMessage.js`

## Next Candidate Moves

- Expand extracted browser-core utility blocks under `node/browser/core/` and keep `node/browser/viewer.js` behavior unchanged via installer/fallback.

Each move should preserve current root entrypoint filenames via small wrappers or symlinks until old build/install paths are retired.
